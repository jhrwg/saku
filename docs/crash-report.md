# 崩溃日志收集

## 用户侧是什么体验

1. App 闪退（或主线程卡死超过 8 秒）时，日志写到本地 `logs/crash-时间戳.log`；
2. 用户**下次打开 App**，底部弹出「上次运行出了点问题」；
3. 点「提交日志」→ 自动上传（国内可直接连），成功提示「日志已提交，谢谢！」；
4. 上传失败（没网 / 服务不可达）→ 自动退回系统分享面板，让用户手动发给你。

同一个崩溃只会打扰用户一次：提交或点「以后再说」都会写 `.reported` 标记。

## 通道

| 通道 | 配置 | 说明 |
| --- | --- | --- |
| 主：ntfy | `CrashReport.NTFY_TOPIC` / `NTFY_SERVER` | 免费、免注册，单条上限 4KB（只传堆栈 + 最近 40 行日志） |
| 备：PushPlus | `CrashReport.PUSHPLUS_TOKEN` | 国内直连最稳，微信收推送，可传 18KB |
| 兜底：系统分享 | 内置 | 上传失败时自动弹出，带 txt 附件 |

当前 ntfy 主题：`vebk-crash-7f3a91`（服务器 `https://ntfy.sh`）

> 主题名相当于收件箱地址，知道名字就能发消息。别改成 `vebk-crash` 这种好猜的名字。

## 怎么收

### 手机（推荐，实时推送）

1. 应用商店 / [ntfy.sh](https://ntfy.sh) 安装 **ntfy** App；
2. 点右上角 `+` → 订阅主题 `vebk-crash-7f3a91`；
3. 之后每台崩溃的手机会推一条通知过来，点开就是完整报告。

### 电脑（偶尔看一眼）

```powershell
# 拉最近的消息（NDJSON）
Invoke-WebRequest 'https://ntfy.sh/vebk-crash-7f3a91/json?poll=1' | Select-Object -Expand Content
```

或用浏览器打开 `https://ntfy.sh/vebk-crash-7f3a91`，网页版直接显示历史消息。

## 国内可用性

实测（2026-11-22）：

| 地址 | 结果 |
| --- | --- |
| `https://ntfy.sh` HEAD | 200，约 1.1s |
| `https://ntfy.sh/<topic>` POST | 200，约 1.2s |
| `https://www.pushplus.plus` HEAD | 200，约 0.25s |

结论：ntfy.sh 没有被墙，能用，但**延迟偏高、偶发失败**（国外服务器）。
所以代码里做了两层保险：

1. 上传超时 6 秒，失败自动走 PushPlus（若配置了 token）；
2. 再失败自动退回系统分享面板 —— 永远不会「点了没反应」。

换自建服务器：把 `NTFY_SERVER` 改成自己的地址（比如国内 VPS 上跑 ntfy），一行搞定。

## 隐私

- 只包含：App 版本、机型、系统版本、崩溃堆栈、运行日志（页面跳转/保存等操作记录）；
- 不包含：账本内容明文、账户余额、头像图片、任何文件附件。

## 后续可加强

- 崩溃时把当前页面 / 最近一次操作一起塞进 `extra`（定位更准）；
- 上传成功后本地只保留 24 小时再删，避免长期堆积；
- 统计崩溃次数（同一堆栈合并），在「我的 → 日志」里展示。
